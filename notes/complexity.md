# 복잡도와 15광년 규모 대입

## 복잡도 식

- 모든 호스트 별 쌍을 한 번씩 검사하는 거리 계산 횟수 상한: `N(N−1)/2`.
- 모든 쌍 간선을 저장하는 추상 메모리: `[N(N−1)/2] × (논리 간선당 바이트)`.
- 이진 힙 다익스트라: `O((N+E) log N)`. N은 호스트 별 수, E는 X 이내인 호스트-호스트 연결 수다.
- 3차원 k-d 트리 반경 질의: 한 번의 비용은 방문 노드 수 `V_i`에 비례하고 최악은 `O(N)`. 별 좌표 분포와 질의 위치를 정하지 않았으므로 보편적 평균식을 단정하지 않는다.
- 지연 질의는 가상 지구 원점에서 1회, 각 확정 호스트에서 최대 1회이므로 질의 횟수 상한은 `N+1`이다. 목표가 확정되면 그보다 일찍 끝날 수 있다.
- 전체 자료를 모두 확장할 때 이웃 반환 횟수 합은 각 별-별 간선이 양 끝에서 한 번씩 반환되므로 최대 `2E`에 지구의 초기 이웃 수가 더해진다.

### 구축 비용의 적용 범위

보고서의 결합 의사코드는 중앙값을 선형 시간 선택으로 구한다고 가정하므로 균형 k-d 트리 구축 비용이 `B(N)=Θ(N log N)`이다. 웹 데모의 실제 `buildKdTree`는 매 재귀 호출에서 해당 부분 배열을 정렬하므로 구축 비용은 `Θ(N log²N)`이다. 따라서 아래 입력별 식에서 `B(N)`은 구현에 따라 대입한다. 또한 데모의 `radiusQuery`는 반환 ID를 정렬하므로 각 질의마다 `O(K_i log K_i)`가 추가된다. 보고서의 알고리즘 비교는 이 구현 세부와 구별되는 의사코드 분석이며, 두 복잡도를 같은 측정 결과처럼 해석하면 안 된다.

## Basic operation 기준 case 분석

강의자료 형식에 따라 입력 크기와 기본 연산을 먼저 구분한다.

- 입력 크기: `N`개 호스트 좌표, X로 정해지는 `E`개 별 간선, 목적지 위치.
- k-d 기본 연산: 질의가 방문한 각 트리 노드의 거리 제곱과 X² 비교. `V_i`는 질의 i에서 방문한 노드 수.
- 다익스트라 기본 연산: `candidate < best[next]` 누적 시간 비교. `R`은 settled 이웃을 건너뛴 뒤 실행된 완화 비교 수.
- 힙 삽입 수 `P≤d_Earth+R`; 각 삽입/삭제는 `O(log(P+1))`.
- 입력별 기본 연산 수는 `N + B(N) + ΣV_i + ΣK_i + R`; `V_i`는 i번째 질의 방문 노드 수, `K_i`는 반환 이웃 수, `R`은 `candidate < best[next]` 비교 수다. `R≤ΣK_i`. 힙 작업 비용을 H라 두면 의사코드 전체는 `Θ(N+B(N)+ΣV_i+ΣK_i+H)`, 힙 상한은 `H=O(P log(P+1))`이다. 데모 코드에는 반환 ID 정렬 비용 `ΣO(K_i log K_i)`도 있다.

### 최선

선형 선택으로 균형 트리를 구축하는 의사코드라면 전체 최선은 `Θ(N log N)`이다. 정렬을 재귀마다 반복하는 데모 구현은 구축만으로 `Θ(N log²N)`이므로 그 구현의 최선도 적어도 이 비용이다. 이미 구축한 트리를 재사용하는 경우에만 구축 비용을 제외할 수 있다.

### 평균 모델

평균 방문 노드 수를 `V̄`, 전체 반환 이웃 수를 K라 두면 조건부 평균식은 `O(B(N) + Q·V̄ + K + P log(P+1))`이다. 반환 ID 정렬을 포함하는 데모 구현은 여기에 `ΣO(K_i log K_i)`가 더해진다. 효과적 가지치기에 대한 별도 분포 가정을 둘 수 있지만, 이번 좌표 자료에서 V̄를 측정하지 않았으므로 평균 실행 성능은 확정하지 않는다.

### 최악 상한

각 k-d 질의가 N개 노드를 전부 방문하고, 전체 E가 `Θ(N²)`까지 조밀해질 수 있다. 질의는 최대 `N+1`회, 반환·완화는 `O(N²)`회, 힙 연산은 `O(N² log N)`이므로 전체 최악 상한은 `O(N² log N)`이다.

## 공간복잡도 단계별 계산

| 저장 대상 | 공간 | 계산 근거 |
|---|---:|---|
| 좌표와 k-d 트리 노드 | `O(N)` | 호스트 별 하나당 좌표와 트리 노드를 저장 |
| `best`, `previous`, `settled` | `O(N)` | 각 호스트 별의 경로 상태를 저장 |
| 현재 의사코드의 우선순위 큐 | `O(P)=O(N+E)` | 더 짧은 후보를 찾을 때마다 새 항목을 삽입하고 오래된 항목은 제거 대신 나중에 건너뜀. 성공 완화는 조사한 전이 간선당 최대 한 번 |
| 반경 질의 결과 목록 | `O(K_max)`, 최악 `O(N)` | 한 질의가 반환하는 후보 별 목록을 임시 저장 |
| 균형 k-d 트리 재귀 스택 | `O(log N)` | 트리 깊이만큼만 호출 프레임이 쌓임 |

따라서 현재 의사코드의 총 보조 공간은 `O(N+E)`이고, 단순 그래프의 밀집 최악은 `E=Θ(N²)`이므로 `O(N²)`이다. 별마다 큐 항목 하나만 유지하고 우선순위를 갱신하는 인덱스 힙(decrease-key)을 사용하면 큐 공간이 `O(N)`이 되어 전체도 `O(N)`으로 줄어든다. 비교 기준 알고리즘은 가능한 간선만 저장하면 `O(N+E)`이며, 모든 별 쌍의 거리나 간선을 보관하는 밀집 표를 쓸 때에만 `O(N²)` 공간을 사용한다.

## 실제 자료와 산출값

2026-11-05 NASA Exoplanet Archive `pscomppars` CSV를 다시 받았다. 호스트 이름으로 묶어 좌표가 있는 항성계만 남겼다. 좌표가 같은 이름 안에서 다르면 평균내지 않고 오류로 중단하도록 분석 스크립트에 처리했다.

- 데이터 행 6,451개, 고유 호스트 4,847개
- 거리/좌표 누락 호스트 28개 제외, 유효 정점 `N=4,819`
- 지구는 가상 출발 정점이므로 호스트 수 N에는 포함하지 않는다.
- 최대 무방향 호스트 쌍: `4,819×4,818/2 = 11,608,971`
- `X=15 ly`의 거리 ≤ X인 호스트-호스트 간선: `E=585`
- 지구에서 첫 도약이 가능한 호스트: 17개
- 지구에서 연결된 도달 가능 호스트: 132개 (전체 유효 호스트의 약 2.74%)
- 도달 가능 성분 내부 호스트-호스트 간선: 339개

도달 가능 성분을 끝까지 탐색하면 k-d 트리 질의는 지구 포함 133회이고, 반환되는 이웃 수 합은 `17 + 2×339 = 695`다. 이는 이 데이터와 X에서의 집계이며, 이론적 상한은 4,820회 질의다.

## 메모리 추정

간선 하나를 16바이트(끝점 정수 2개와 거리 실수 1개)로 저장한다고 가정한다. 이는 구현체의 실측 메모리가 아니라 비교용 밀집 저장 포맷이다.

- 585개 실제 호스트 간선 저장: `585×16 = 9,360 bytes` (약 9.14 KiB)
- 가능한 호스트 쌍 11,608,971개를 전부 저장: `185,743,536 bytes` (약 185.74 MB 또는 177.14 MiB)
- 지구까지 포함해 모든 쌍을 저장하는 상한은 정점 4,820개, 간선 11,613,790개다. 같은 가정이면 `185,820,640 bytes` (약 177.21 MiB)다.

현재 카탈로그 규모에서 전수 저장은 이 가정상 메모리 측면에서 가능하다. 지연 질의의 이점은 “전수 저장이 메모리 불가능”하다는 주장이 아니다. `X=15 ly`에서 전체 호스트 쌍 11,608,971개를 비교하는 대신, 도달 가능한 성분을 탐색하면서 가까운 이웃만 질의한다는 점이다. 작은 E가 나온 것은 이번 자료와 거리 한계에서 확인된 결과다.
