| 문서 위치 | 이 파일(`web-demo/docs/interstellar-route-demo-plan.md`). `web-demo/README.md`는 확정 결정 요약 |

**전제**
- 간선 비용(카탈로그 모형 정의, **출발 호스트 기준**): `w(u→v) = 거리(ly) / 속도(c 배수) + (u가 지구가 아니면 기착 1년, u가 지구면 0)` — 모든 비용이 비음수이므로 Dijkstra 조건을 만족합니다.
- 중간 `best[v]`(코드상 `distYr[v]`)는 **"v에 도착한 시각"**입니다. v에서의 기착은 v를 떠날 때(v의 모든 나가는 간선에) 붙습니다. 목적지가 settle되면 탐색을 종료하므로 목적지에서의 기착은 붙지 않습니다.
- 출발지는 지구(=태양, 원점 (0,0,0)). 1 AU ≈ 1.6e-5 ly라 무시합니다.
- 카탈로그 분석에서 HD 199509는 지구에서 약 79.274광년, X=15광년에서 도달 가능하며 최단시간 경로는 호스트 12곳·기착 11회·약 1,509.5325년입니다. subset 결과는 카탈로그 분석과 다를 수 있으므로 About/푸터에 출처만 표기합니다.
- AI(Claude/Cursor)는 구현·시각화·문구·배포 보조용이며, 경로를 추론하는 엔진이 아닙니다.

**초기 구상과의 관계**: 원래 구상은 "태양계 한정 웹"이었지만, 교육 효과(반경 X 질의와 경유 기착이 의미를 갖는 스케일) 때문에 **MVP = 합성 항성(B), v1 = 호스트 subset(C)**로 진행합니다. 태양계(A)는 그래프 데모가 아니라 인트로의 거리 단위 설명용입니다.

## 1. 한 문장 제품 정의

별 사이 도약 거리 X, 속도, 기착 시간을 조절하며 **Dijkstra가 별을 확정하고 k-d 트리 반경 질의가 이웃을 고르는 과정을 3D에서 단계별로 재생**해 최단시간 경로를 찾는 웹 앱. 실제 우주선 항법이 아닌 정적 좌표 기반 단순화 모형이다.

### 3.1 3D 모션 스펙

참고: NASA Eyes(카메라·대상 추적·레이어 UX), Sketchfab 태양계(인트로 비주얼만).  
알고리즘 그래프는 항상 **점 + 반경 구 + 경로 선**. 실시간 궤도/천체력은 Out.

| 단계 | 모션 |
|---|---|
| 기본 | OrbitControls 회전/줌 + 시점 초기화 |
| `pop` / `settle` / `query` | 현재 별이 화면 밖일 때만 카메라 **lerp** 추적. 텔레포트 금지. 사용자 조작 시 추적 중단 |
| `query` | 반경 구 fade-in → 이웃 pulse → (선택) 중심↔이웃 짧은 선 |
| `relax` | 완화 간선 잠깐 표시 후 소멸(갱신분만 강조) |
| `done` | 최종 경로 금색(`#FFEA00`) **순차 연결** |
| 인트로(선택) | 미니 태양계는 거리 단위 설명용. 탐색 캔버스와 **모드 분리** |

금지: 전별 라벨 상시, k-d 분할면 오버레이, 무거운 그림자/성운, Eyes급 텍스처·미션 타임라인.

## 4. 핵심 사용자 플로우

1. **처음 학습**: 접속 → 프리셋 확인 → ▶ 반복(확정 → 질의 → 갱신) → 결과 카드 → "왜 이 경로?" 문구 확인
2. **what-if 탐험**: X 슬라이더 감소 → "도달 불가" 안내 → X 증가 → 경로·도약 수·기착 수 변화 확인 (v1: 이전 경로 점선 오버레이)
3. **실데이터 시나리오(v1)**: 데이터셋 C로 전환 → 목적지 검색(HD 199509 프리셋) → 자동재생 → 결과 + About/푸터 출처 확인

## 5. 데이터 모델과 출처 원칙

**모델**
- **Body**: `id, name, pos[x,y,z] (ly), kind(earth | host | synthetic), datasetId`
- **Dataset 메타**: `name, source, retrievedAt, citation, frame(ICRS 직교), unit(ly), isSynthetic`
- **Jump(간선)**: 저장하지 않고 질의 시 계산. `from, to, distLy, travelYr, stopYr, costYr` — `stopYr`는 **출발 호스트 `from` 기준**(from이 지구면 0, 아니면 기착 시간), `costYr = travelYr + stopYr`
- **SearchState**: `distYr: Map(v에 도착한 시각, v의 기착 미포함), prev: Map, settled: Set, pq 스냅샷, currentId, lastQuery{center, radius, hitIds}`
- **Path**: `nodeIds[], legs[], totalYr, hops`
- **Scenario/Params**: `datasetId, startId(=earth), destId, X, speedC, stopYr`

**출처 원칙**
- 실데이터는 NASA Exoplanet Archive pscomppars에서 오프라인 스크립트(`scripts/`)로 변환합니다. 런타임 외부 호출은 없습니다.
- 변환: `ra, dec, sy_dist(pc)` → ly(1 pc ≈ 3.26156 ly) → 직교좌표. 결측은 제외, hostname 기준 중복 제거. 컬럼명은 구현 시 재확인합니다.
- 모든 데이터셋은 UI에 출처, 취득일, 합성 여부를 표기합니다.
- 좌표는 항상 3차원 `[x,y,z]`. MVP 합성 데이터도 3D입니다.

**v1 subset 절단 규칙 (200~500개)**
- 지구에서 도달 가능한 연결 성분(프리셋 X 기준)을 우선 포함하고, 도달 불가능한 별만으로 채우지 않습니다.
- 절단 방식은 **카탈로그 최단경로(Earth → … → HD 199509) + 경로 주변 이웃 보강**입니다. 경로 주변에 편향될 수 있으므로 UI 고지를 유지합니다.
- HD 199509 프리셋 경로가 끊기지 않도록 변환 스크립트에서 assert합니다.
- 연결성 assert가 실패하면 빌드를 중단합니다.
- About·푸터에 출처·합성 여부·시드만 표기합니다.

## 6. 단계 재생 상태머신

알고리즘은 **이벤트 로그를 먼저 전부 생성**하고, UI는 인덱스만 움직입니다. 뒤로 가기·스크럽이 공짜로 되고 데모 규모(수백 개)에서 메모리 부담이 없습니다. 파라미터가 바뀌면 재계산합니다.

| 단계 | 의미 | 이벤트 payload |
|---|---|---|
| `idle` | 시나리오 미선택 / 파라미터 편집 중 | - |
| `ready` | 초기화 완료, 출발지 dist=0 | 초기 큐 |
| `pop` | 큐에서 최소 도착 시각 노드 선택. 동률이면 노드 id 오름차순 | nodeId, distYr |
| `settle` | 해당 노드 확정(이후 불변). 목적지면 탐색 종료 | nodeId |
| `query` | k-d 반경 X 질의 | center, radius, hitIds, 방문 k-d 노드 수 |
| `relax` | 이웃별 후보 도착 시각 = `distYr[u] + stop(u) + 거리/속도` 계산 후 갱신/무시. `stop(u)` = u가 지구면 0, 아니면 기착 | from, to, travelYr, stopYr, candidateYr, updated |
| `done` | 목적지 확정, 경로 복원 | path |
| `unreachable` | 큐 소진, 목적지 미도달 | settledCount |

- 한 사이클: `pop → settle → query → relax*`. 목적지가 `settle`되면 즉시 `done`(목적지 기착은 계산하지 않음).
- 기착은 **settle된 노드 u를 떠날 때** u의 모든 나가는 간선에 동일하게 붙습니다. UI 계산식도 `distYr[u] + 기착(u) + 거리/속도`로 보여줍니다.
- "한 단계" 버튼 = 한 사이클 묶음. "세부 보기" 토글로 하위 단계를 쪼개 봅니다.
- 재생 컨트롤 상태(`paused / playing`)는 알고리즘 단계와 별도로 관리합니다.

## 7. 기술 스택

**추천: Vite + React + TypeScript + Zustand**
- 3D: react-three-fiber + drei (OrbitControls)
- 테스트: Vitest
- `src/core`는 프레임워크 무관한 순수 TS (좌표/단위, k-d 트리, Dijkstra 이벤트 생성). UI와 분리합니다.
- k-d 트리는 **3D 직접 구현**: 방문 노드 수 기록이 필요하고 흔한 라이브러리는 2D 위주입니다. 브루트포스와 결과 비교 테스트를 붙입니다.
- 정적 배포라 서버가 필요 없습니다.

**대안: Next.js (App Router, static export)**
- OG 이미지, 다국어 라우팅, API 라우트가 필요해질 때 유리합니다.
- 이번 범위에서는 SSR이 불필요해 설정 부담만 늘어납니다.

## 9. 리스크와 함정

**3D 가독성 (3D 직행으로 새로 생기는 위험)**

| 위험 | 대응 |
|---|---|
| 깊이감이 없어 "누가 반경 안인지" 안 보임 | 반경 구를 반투명으로 그리고, 이웃은 색과 크기로 강조, 중심↔이웃 선 연결 |
| 별 가려짐/겹침 | OrbitControls + 화면 밖일 때만 lerp 추적(§3.1), 사용자 조작 시 중단 |
| 카메라 길 잃음 | "시점 초기화" 버튼 |
| 색에만 의존한 상태 표시 | 확정/후보/이웃/경로를 색 + 모양(크기, 외곽선)으로 이중 인코딩 |
| MVP 범위 팽창 | 그래프="구 + 하이라이트 + 선". Eyes/Sketchfab은 UX·인트로만 |
| 궤도 시뮬 욕심 | 실시간 천체력·전 태양계 물리 금지. Sketchfab식은 인트로 모드만 |
| 모바일 3D 성능 | InstancedMesh 사용, 데모 규모(수백 개) 유지, v1에서 실기기 확인 |

**기타**
- **좌표계**: ICRS 적도좌표 기준 직교 변환. 은하좌표와 혼동하지 않습니다.
- **단위**: pc↔ly, 거리/속도 → 년 계산을 `core/units` 한 곳에서만 합니다. UI 표기 단위와 계산 단위를 분리합니다.
- **경계값**: `거리 ≤ X` 포함 여부와 부동소수점 오차(카탈로그 모형 정의와 맞출 것). 쌍성 등 거리 0 별도 처리.
- **Dijkstra 구현**: lazy deletion 시 큐에 낡은 항목이 남으므로, 스냅샷에는 최신 항목만 보여줍니다. 동률은 노드 id 오름차순.
- **subset 왜곡**: subset을 자르면 연결성과 최단 경로가 카탈로그 분석과 달라집니다. §5 절단 규칙(연결 성분 우선, 경로+이웃 보강, HD 199509 경로 assert)을 지키고 About/푸터에 출처만 표기합니다.
- **기착 비용 혼동**: 도착 노드 기준(`v가 목적지가 아니면 +1년`)으로 구현하면 최종 총합은 같아질 수 있어도 중간 레이블(`distYr`)과 UI 계산식이 카탈로그 경로 예시와 어긋납니다. 항상 **출발 호스트 기준**으로 구현합니다.
- **성능**: 수백 개는 문제없음. 전체 N≈4819는 이벤트 로그가 커지므로 Web Worker가 필요하며 이번 범위 밖.
- **카탈로그 결과와 혼동**: 데이터셋 배지(합성/실데이터), 고지 문구, 카탈로그 결과와의 구분 문구를 넣고 태양계 데이터는 섞지 않습니다.
- **실시간 오해**: About에 "정적 좌표 기반"임을 명시합니다.

## 10. 후속 프롬프트 초안 (Claude/Cursor용)

### (1) 프로젝트 스캐폴딩
```
Vite + React + TypeScript 프로젝트를 만들어줘. 코드는 최소한으로, 요청한 것만.
작업 위치: exoplanet-hop/web-demo/
구조: src/core(순수 TS: units, kdtree, dijkstra 이벤트 생성), src/data(정적 JSON),
src/ui(패널/캔버스/컨트롤), src/store(Zustand).
요구: Vitest 설정, core는 React 의존 금지, 좌표는 항상 [x,y,z] (ly).
시각화: @react-three/fiber + @react-three/drei(OrbitControls)로 3D 캔버스를 기본으로 설정.
출발지는 지구 고정. 기착은 출발 호스트 기준(지구 0, 그 외 1년, 목적지 settle 시 종료).
먼저 만들 것:
 (a) units: pc→ly, 거리/속도→년
 (b) 합성 3D 데이터셋 생성기(시드 고정, 80~150개, 프리셋 X에서 연결 그래프 보장 assert)
 (c) 헤더에 워드마크 EXOPLANET HOP + 데이터 필(합성 항성 N · 0.1c · X N ly)이 있는 빈 레이아웃.
     중앙은 R3F <Canvas>, 별은 InstancedMesh, 시점 초기화 버튼 포함
 (d) 그래프 본체는 점·구·선만. 궤도 역학/성운/그림자맵 금지(§3.1).
애매한 점이 있으면 구현 전에 질문하고, 가정은 명시해줘.
완료 기준: dev 서버 실행, 단위 변환 테스트 통과, 3D 캔버스에 별이 렌더링되고 시점 초기화가 동작함.
설계 문서는 web-demo/docs/interstellar-route-demo-plan.md, web-demo/docs/prebuild-handoff.md, web-demo/README.md 를 따른다.
```

### (2) 알고리즘 단계 시각화
```
src/core에 3차원 k-d 트리(축 순환 x→y→z, 반경 질의, 방문 노드 수 반환)와,
이벤트 로그를 만드는 Dijkstra를 구현해줘.
비용(카탈로그 모형 정의, 출발 호스트 기준): w(u→v) = 거리(ly)/속도(c) + (u가 지구가 아니면 기착 1년, 지구면 0).
dist[v]는 'v에 도착한 시각'이고, v의 기착은 v를 떠날 때 붙는다. 목적지가 settle되면 탐색을 종료한다(목적지 기착 없음).
동률(pop)은 노드 id 오름차순.
이벤트: ready, pop, settle, query, relax, done, unreachable
 (payload: pop{nodeId, distYr}, query{center, radius, hitIds, visitedKdNodes},
  relax{from, to, travelYr, stopYr, candidateYr, updated}, done{path}, unreachable{settledCount}).
테스트: (1) k-d 반경 질의 == 브루트포스 (2) 이벤트 로그 Dijkstra == 전수 간선 Dijkstra (3) 손계산 소규모 그래프에서 출발 호스트 기준 기착 비용 일치.
그 다음 UI:
 - 이벤트 인덱스 기반 재생(◀ ▶ 스크럽, 자동재생), "한 단계" = pop~relax 묶음, 세부 보기 토글
 - query 단계: 반경 구 fade-in + 이웃 pulse + (선택) 중심↔이웃 선
 - pop/settle/query: 현재 별이 화면 밖일 때만 카메라 lerp 추적(텔레포트 금지, 사용자 조작 시 중단)
 - relax: 완화 간선 잠깐 표시. done: 최종 경로 금색 순차 연결
 - 상태는 색과 크기/외곽선으로 이중 표기(확정/후보/이웃/경로)
 - 우측에 한 문장 설명 + 계산식
 - 실시간 궤도/천체력/k-d 분할면/전별 라벨 금지(§3.1)
파라미터 변경 시 로그 재생성. 기존 파일은 요청 범위 밖은 건드리지 마.
```
